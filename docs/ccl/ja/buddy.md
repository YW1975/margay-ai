# Buddy：チームメイトと軽量レビュー

<!-- section: availability -->

<!-- section: ordinary -->
## チームメイトを起動する

メインセッションを手伝うチームメイトが必要な場合は、通常の Buddy を使います。

```text
/buddy 移行計画にロールバック手順の抜けがないか確認してください
/buddy --team migration --name researcher 二つの API 契約を比較してください
```

`--team` の既定値は `buddy-team`、`--name` の既定値は `reviewer` です。タスクを省略すると、Buddy はメインエージェントに現在の会話から最も取り組みやすい作業を選ばせます。名前に `reviewer` または `critic` が含まれる場合、チームメイトの指示にレビューの役割が加わります。

通常の `/buddy` はプロンプトに展開されます。メインエージェントは先に `TeamCreate` を呼び、適切なら現在のチームを再利用し、`TeamCreate` が実際に返したチーム名と指定したメンバー名で `Agent` を呼ぶ必要があります。既に別のチームを率いている場合は競合を報告します。プロンプトが生成されただけでは起動の証拠になりません。作業を利用する前に Team と Agent の結果を確認してください。

<!-- section: peer-review -->
## 保護されたピアレビューを依頼する

開発作業に保護された提出物と独立したレビュー判定が必要なら、明示的にレビューモードを使います。

```text
/model
/buddy --peer-review --reviewer-model <固定モデルID> パーサーを修正し、回帰テストを追加してください
```

先に `/model` で具体的な開発モデルを選び、レビュー側のプレースホルダーを利用可能な固定モデル ID に置き換えます。このモードではレビューモデルに `auto`、`smart`、`pool`、`inherit`、`default` は使えず、開発目標が必要です。`--team <名前>` と `--name <レビュアー名>` も指定できますが、レビュアー名を `team-lead` にはできません。

メインエージェントは保護タスク付きの Team を作り、そのタスク ID を使って `code-reviewer` Agent を起動します。開発者が現在の資料を提出すると、レビュアーは提出スナップショットを確認・テストし、その提出物に PASS または NEEDS_WORK を返します。証拠を添えた異議も出せます。新しい提出には新しいレビューが必要です。現在の提出物に対するレビュアーの PASS のみが保護された Buddy タスクを完了できます。取消、一時停止、上限到達は未完了のままです。この従来のレビュー経路では、通常のレビューツールに独立したスナップショットを使います。[Duo](duo.md) には別の完了条件があり、異なる二つの実際のモデルリクエスト、現在のレビュー、実行者の受け入れが必要です。現在の Duo レビュアーは通常の作業領域を確認できます。

<!-- section: limits -->
## 結果を確認する

どちらの Buddy も Team と Agent の実際のツール実行に依存します。チームメイトと保護タスクの状態を確認してください。生成されたプロンプトやモデルの成功宣言だけでは完了しません。レビュー用コピーやツール権限は、同一ユーザーで実行される悪意あるコマンドを隔離する OS サンドボックスではありません。CCL の再起動後に進行中の協働が自動復元される保証はありません。
